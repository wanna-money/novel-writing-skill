# 上下文连贯性管理详解

> 防止章节之间出现不连贯——长篇写作中最容易被忽视也最致命的问题。

---

## 一、为什么连贯性管理是必须的

长篇小说（尤其是AI辅助写作时）最常见的问题：

1. **人物称呼不一致**：第三章叫"小凡"，第十章突然叫"张小凡"，第二十章又叫"凡哥"
2. **时间线错乱**：角色A在第五章说"三天前发生了那件事"，但那件事实际发生在第二章的一个月前
3. **空间瞬移**：角色上一章还在山上，下一章突然在城里，没有任何交代
4. **性格突变**：一直冷静的角色突然变得情绪化，没有触发事件
5. **设定矛盾**：第二章说"法术需要三天冷却"，第十章同一个法术一天用了两次
6. **伏笔丢失**：埋了伏笔忘了回收，或者回收时细节对不上
7. **关系断层**：两个角色之间发生了重要事件，之后的互动完全没有受到影响

## 二、章节总结制度

**铁律：每写完一章，必须填写章节总结，然后才能开始下一章。**

### 章节总结模板

```
=== 第X章「章节标题」总结 ===
写作日期：YYYY-MM-DD

【故事时间】
  本章时间范围：从___到___
  相对时间：距离故事开始已过___

【情节推进】（3-5句话概括核心事件）
  1. ___
  2. ___
  3. ___

【人物状态更新】
  [角色A]：
    - 当前位置：___
    - 心理状态：___
    - 关键变化：___
    - 与其他角色关系变化：___
  [角色B]：
    - ...

【伏笔状态】
  新埋伏笔：
    - [伏笔ID-xx] ___（预计在第X章回收）
  已回收伏笔：
    - [伏笔ID-xx] ___（回收方式：___）
  仍在等待的伏笔：
    - [伏笔ID-xx] ___（状态：___）

【世界观揭示】
  本章揭示了什么新信息：___
  读者现在对世界的理解到了第___层

【重要物品/道具】
  新出现：___
  状态变化：___（如：法宝受损、药品用尽等）

【下章衔接要点】
  本章结尾状态：___
  下章开头需要衔接：___
  注意事项：___

【自查清单】
  □ 人物称呼是否与前文一致？
  □ 时间线是否连贯？（与上一章的时间间隔合理吗？）
  □ 空间位置是否合理？（角色怎么到达当前位置的？）
  □ 人物性格表现是否一致？（有无无理由的OOC？）
  □ 已建立的设定是否被违反？
  □ 对话风格是否与角色一致？
  □ 上一章的章末钩子是否在本章得到了回应？
```

## 三、四个核心追踪文件

在写长篇小说时，除了每章的总结外，还需要维护四个独立的追踪文件：

### 3.1 章节总结汇总（chapter-summaries.md）

所有章节总结的汇总文件。每次写新章节前，必须先读取此文件的**最近5章**内容，确保衔接。

```
格式：
# 章节总结汇总

## 第一章「标题」
[简要总结，100-200字]
关键状态：___

## 第二章「标题」
[简要总结，100-200字]
关键状态：___

...
```

### 3.2 人物档案（characters.md）

所有出场角色的实时状态。随故事推进持续更新。

```
格式：
# 人物档案

## 主要角色

### [角色名]
- 称呼：___（列出所有使用过的称呼）
- 外貌特征：___（固定不变的描写）
- 说话风格：___（用词习惯、语气特点）
- 当前状态：___（随故事更新）
- 重要经历：___（按时间顺序列出）
- 人物关系：___（与其他角色的关系及变化）
- 能力/境界：___（当前等级和标志性能力）

## 次要角色

### [角色名]
- 身份：___
- 登场章节：第X章
- 关键特征：___（一笔定型的细节）
- 与主角关系：___
```

### 3.3 伏笔追踪表（foreshadowing-tracker.md）

所有伏笔的生命周期管理。

```
格式：
# 伏笔追踪表

## 待回收

| ID | 伏笔内容 | 埋入章节 | 预计回收章节 | 回收方式 | 状态 |
|----|---------|---------|------------|---------|------|
| F-001 | 主角梦见的红色光芒 | 第2章 | 第15章 | 与法宝觉醒相关 | 等待中 |
| F-002 | 老人临终的那句话 | 第5章 | 第10章 | 在秘境中得到验证 | 等待中 |

## 已回收

| ID | 伏笔内容 | 埋入章节 | 回收章节 | 回收方式 |
|----|---------|---------|---------|---------|
| F-003 | 师父的旧伤 | 第3章 | 第8章 | 战斗中旧伤复发 |

## 已放弃（说明原因）

| ID | 伏笔内容 | 原因 |
|----|---------|------|
```

### 3.4 世界观设定（worldbuilding-notes.md）

所有已展示的设定（注意：只记录已在正文中展示过的，未展示的放在大纲里）。

```
格式：
# 世界观设定笔记

## 已展示的规则
- [规则1]：在第X章通过[事件]展示
- [规则2]：在第X章通过[对话]展示

## 已展示的地理
- [地点A]：第X章首次出现，描述为___

## 已展示的历史
- [历史事件A]：第X章提及，说法是___

## 待展示（大纲中计划但尚未写入正文的）
- [规则/地点/历史]：计划在第X章展示
```

## 四、每次开始新章节前的标准流程

```
Step 1：读取最近5章的章节总结
Step 2：读取当前人物档案
Step 3：读取伏笔追踪表（检查本章是否有需要回收的伏笔）
Step 4：读取世界观设定笔记（检查是否有需要遵守的设定）
Step 5：读取本章的章纲
Step 6：开始写作
Step 7：写完后填写本章总结
Step 8：更新人物档案、伏笔追踪表、世界观设定（如有变化）
```

## 五、上下文窗口管理策略

AI辅助写作时，上下文窗口无法容纳全部小说文本。必须使用以下策略来保证连贯性：

### 5.1 分层记忆

```
第一层（始终加载）：
  - 总纲（核心矛盾、主题、起止点）
  - 人物档案（最新版本）
  - 当前卷纲

第二层（写新章节时加载）：
  - 最近5章的章节总结
  - 伏笔追踪表
  - 当前章的章纲

第三层（需要时按需加载）：
  - 世界观设定笔记
  - 某个特定章节的全文（需要精确衔接时）
  - 某个角色的详细历史
```

### 5.2 "锚点回忆"技法

当写到需要回顾前文的情节时，不要凭记忆——回去读原文。具体方法：

```
如果当前章节提到了第X章的事件：
  1. 打开第X章的章节总结，确认事件细节
  2. 如果总结不够详细，打开第X章原文
  3. 确保当前章节的描述与原文一致
  4. 如果有意改变描述（如角色的回忆偏差），标注这是故意为之
```

### 5.3 "交叉验证"

每写5章，做一次交叉验证：

```
验证项目：
1. 抽查3个角色的称呼是否全书一致
2. 画出最近5章的时间线，检查是否有矛盾
3. 检查所有已埋伏笔的状态（是否该回收了？）
4. 检查当前章节的设定是否与前文冲突
5. 检查角色的能力等级是否与前文一致
```

## 六、常见连贯性错误及预防

| 错误类型 | 典型表现 | 预防方法 |
|---------|---------|---------|
| 称呼混乱 | 同一角色在不同章节用不同称呼 | 人物档案中列出所有合法称呼 |
| 时间线错乱 | "三天前"指向错误事件 | 每章标注故事时间，用绝对时间 |
| 空间瞬移 | 角色无故切换位置 | 章节总结中必须记录角色位置 |
| 能力失忆 | 关键时刻忘了角色会的技能 | 人物档案中维护能力列表 |
| 性格突变 | 无触发事件的性格变化 | 性格变化必须在章节总结中标注原因 |
| 伏笔遗忘 | 埋了没收，或收了对不上 | 伏笔追踪表，每5章审查一次 |
| 设定矛盾 | 违反之前建立的世界规则 | 世界观设定笔记，写前查阅 |
| 信息泄漏 | 角色知道了他不应该知道的事 | 在章节总结中标注"角色A目前知道/不知道什么" |
